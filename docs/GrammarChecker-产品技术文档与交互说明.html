SECTION 01

产品概述与技术描述

GrammarChecker 是一款部署在个人电脑上的轻量英语语法检查网页工具。用户在浏览器中使用，核心能力由大语言模型（LLM）提供，包括：语法检查与纠错、句子翻译、句子结构分析、近义词场景辨析、中文意译表达推荐。

技术描述要点

维度说明
产品形态网页工具（Web App），桌面浏览器访问，设计基准 1440 × 900
架构方式前后端分离：前端为单页应用（SPA），后端提供 REST JSON API，通过 HTTP 本机回环通信
开发语言后端采用 Go 语言；前端 HTML/CSS/JS（框架选型由开发定，建议 Vue 3 或 React 任一轻量方案）
部署方式个人电脑本地部署：后端编译为单一可执行文件，静态前端资源通过 go:embed 嵌入，无需安装任何运行时依赖；启动后监听 127.0.0.1（默认端口建议 :8899），可自动拉起浏览器
数据库SQLite，单文件数据库（建议 grammar.db）存储在个人电脑本地；无服务器、无外部数据库依赖。驱动建议 modernc.org/sqlite（纯 Go、免 CGO，利于交叉编译）
AI 能力语法检查 / 翻译 / 结构分析 / 辨析 / 表达均调用外部 LLM 服务（兼容 OpenAI 接口格式）；API KEY 由用户在配置页填写，仅保存在本地 SQLite，随请求携带，不落第三方
隐私边界除发往 LLM 的检查/辨析/表达请求外，所有用户数据（错词、例句、历史、密钥）均不出本机
设计稿以「Flutter App UI」命名，但当前交付的 7 屏均为桌面浏览器网页布局（左侧固定侧边栏 + 右侧自适应主内容区），与「网页工具」的技术描述一致；若后续需要 Flutter 壳封装（如 WebView 桌面壳），本交互文档同样适用。

SECTION 03

数据模型（SQLite）

所有表由后端在首次启动时自动建表（含索引）。时间字段统一 TEXT（ISO 8601）。

表名字段对应页面
wrong_words
错词本 / 先前错误		 id · word 错误词 · error_type 错误类型（主谓一致/名词复数/时态混用/所有格误用/不可数名词/比较级误用…）· original_sentence · corrected_sentence · analysis_json 结构分析缓存 · created_at 仓库-先前错误；检查页「加入错词本」
sentences
例句收藏		 id · english 英文句子 · chinese 中文翻译 · source 来源（check/manual）· analysis_json 结构分析缓存 · created_at 仓库-例句；检查页「收藏例句」（如有）
discriminations
辨析记录		 id · word 辨析词 · synonyms_json 近义词列表 · result_json 场景辨析结果 · favorite 收藏标记（0/1，2026-09-25 新增） · created_at 仓库-辨析（示例卡）；辨析页历史复用
expressions
表达记录		 id · chinese 中文原句 · recommended 推荐译法 · variants_json 三变体（口语/书面/简洁，含场景+例句+译文）· favorite 收藏标记（0/1，2026-09-25 新增） · created_at 表达页
check_history
检查历史		 id · sentence · error_count 错误数 · result_json 完整检查结果 · created_at 检查页「历史记录」卡片；趋势页统计源数据
settings
系统设置（KV）		 key · value。预置键：api_key（LLM 密钥，本地保存）、reuse_discrimination_history（辨析复用历史开关，默认开） 配置页
comp_infos
成分说明字典（2026-09-25 新增）		 role 主键（成分名）· what 是什么 · why 有什么用 · how 怎么用 · demo 示例。启动时预置 23 个角色的语法知识 seed，运行期只读，查询不调 LLM 成分说明弹窗（检查页结构卡 / 仓库两个结构弹窗）
辨析历史不单独建表：辨析页历史 = discriminations 表按时间倒序，受配置页「辨析复用历史记录」开关控制是否读取。收藏为记录上的 favorite 标记位（幂等写入、取消不删记录），不单独建收藏表。
SECTION 04

后端 API 接口草案

REST 风格，统一前缀 /api，请求/响应均为 JSON。涉及 LLM 的接口为同步长请求（建议前端 loading 态 + 后端 60s 超时）。

接口方法说明
/api/checkPOST语法检查。入参 {text}（≤500 字符）；返回契约以前端 mock 为准：{errTotal, translation, errors:[{type,fix,desc}], example, idiomatic, struct}；后端同时写入 check_history
/api/wrong-wordsGET先前错误列表。查询参数：q（搜索单词）、type（错误类型胶囊）、from/to（日期区间）；类型与日期为 AND 组合
/api/wrong-wordsPOST新增错词（检查页「加入错词本」倒计时结束调用）。请求体：word（必填）、error_type、original_sentence、corrected_sentence、analysis_json；返回 201 与完整记录
/api/wrong-words/{id}DELETE删除单条错词
/api/sentencesGET / POST例句列表（q 搜索例句）与新增；POST 支持可选 analysis_json（结构分析缓存，取自 check 响应 struct 段）与 source（manual 默认 / check=检查页收藏例句），非法 source 返回 400
/api/sentences/{id}DELETE删除例句收藏
/api/discriminationsGET辨析收藏/历史列表（q 搜索收藏的解析、日期筛选、favorite=1/0 收藏状态过滤）
/api/discriminations/{id}DELETE删除单条辨析记录（2026-09-25 新增，仓库·辨析选项卡编辑模式）。不存在 404，id 非法 400
/api/discriminatePOST辨析。入参 {word, reuse_history}；开关开启时先查本地 discriminations，命中直接返回不请求 LLM
/api/discrimination-historyDELETE清空辨析历史
/api/expressPOST表达。入参 {text}（中文）；返回契约以前端 mock 为准：{core, words:[{chip,solid,pos,scene,en,zh}]}；写入 expressions
/api/expression-historyGET / DELETE表达历史列表（limit、favorite=1/0 过滤）与清空
/api/history/checkGET / DELETE检查历史列表（近 N 条）与清空
/api/trendsGET趋势统计。参数 type（错误类型筛选）、range；返回 {points:[{date,accuracy}], summary:{today,avg,delta}}
/api/settingsGET / PUT读取/保存设置项（API KEY、辨析复用开关）
/api/comp-infoGET句子成分说明（2026-09-25 新增）。查询参数 role（需 URL 编码）；返回 {role, what, why, how, demo}；内容为启动时预置 DB 的固定语法知识 seed（23 个角色），只读 DB 不调 LLM；未收录角色 404，前端回退通用说明
/api/discriminations/{id}/favorite
/api/expression-history/{id}/favorite		POST / DELETE收藏 / 取消收藏（2026-09-25 新增）。标记位语义：写入幂等、取消不删除记录；记录不存在 404；配合列表 favorite 过滤
/api/llm/usage-examplePOST成分用法示例生成（2026-09-25 新增，挂起）。入参 {sentence, role}；LLM 接通后返回 {example}；当前返回 400 api_key_missing / 501 prompt_pending

SECTION 06

页面交互说明

以下按导航顺序逐页说明。每页给出：布局结构 → 控件与交互规则 → 数据依赖。

6.1 检查页（默认首页）

核心流程页 副标题「输入英语句子，检查语法并获取翻译」。

  • 页头行：左侧标题列；右侧「历史记录」按钮（时钟图标 + 文字，白底发丝线圆角 8）。
  • 输入卡片：
    • 标签行：『输入句子』+ 右侧字数统计 70 / 500（上限 500 字符，实时递增）。
    • 输入区（灰底圆角 12 多行输入）：错误词在输入框内即时高亮——红色 14% 透明底、圆角 4，如示例中 have went；文本光标为 2×20 蓝色竖线。
    • 操作行：左侧快捷键提示 Ctrl + Enter 快速检查；右侧按钮组—— 「加入错词本」按钮（见下方状态流转）与 「检查」主按钮（蓝底白字胶囊）。
  • 「加入错词本」按钮状态流转（5 秒倒计时自动加入）：
    1. 检查发现错误后按钮呈红色（实心红胶囊）；
    2. 点击后进入倒计时态：按钮显示 5s → 1s 递减数字，进度环同步擦除；
    3. 倒计时期间再次点击红色按钮可取消本次自动加入；
    4. 倒计时结束自动写入错词本（wrong_words），按钮回到初始态并给予轻量反馈。
  • 结果卡片行（检查完成后展示，两卡并排）：
    • 检查结果卡片：标题行『检查结果』+ 蓝色统计『发现 1 处语法问题』；依次分区——翻译（中文全句）、错误原因（灰底错误条目：错误词、类型、原因、修改建议）、示例（正确用法例句）、地道表达（更地道的替代说法）。
    • 句子结构分析卡片（480 宽，标注「基于修正后的句子」）：句子成分（成分标签 + 内容的横向对，如「主语」「名词短语 your letter」）、句子结构（一句话概括，如「主从复合句：让步状语从句前置…」）、从句分析（灰底内衬）、时态。
  • 历史记录卡片（点击页头按钮，自页头右侧下方弹出）：标题行『历史记录 + 条数 + ✕』，淡分隔线，5 条历史条目——每条为检查过的句子 + 右侧错误数芯片（有错误=红 / 无错误=绿），底部「清空」按钮；点击条目可将句子回填输入框。

数据依赖：POST /api/check、GET/DELETE /api/history/check、错词本写入。

6.2 仓库页 · 先前错误（默认选项卡）

副标题「存储来自检查、手动添加的例句」。仓库页通过分类选项卡切换三个视图：先前错误 / 例句 / 辨析，激活项为蓝底白字胶囊（圆角 999）。

  • 列表头部：左侧列表标题『先前错误 · 24 个词条』；右侧筛选组（靠右对齐）——日期筛选按钮（日历图标 + 09-01 ~ 09-24 + 下拉箭头）与搜索框（放大镜 + 占位『搜索单词』，胶囊形）。
  • 类型筛选胶囊行：按错误类型显示计数胶囊——主谓一致 · 8（实心红）、名词复数 · 6、时态混用 · 4、所有格误用 · 3、不可数名词 · 2（红色按计数递减透明度）、比较级误用 · 1（灰底）；旁注『点击胶囊筛选该类型，再点一次取消』。
  • 词条网格：两列卡片网格（间距 12，三行示例：went / children / been / theirs / advice / better）。每卡：左侧词条信息（错误词 + 类型标签等，容器 hug_contents 避免胶囊被裁切）+ 右侧操作。
  • 筛选组合逻辑：类型与日期两个条件同时生效（AND），列表标题与词条计数随筛选结果实时更新；日期筛选『自定义区间』打开日历范围选择器。
  • 点击语法错误卡片 → 弹出「句子结构分析」弹窗（560 宽白卡圆角 18，以 went 为例演示）。

数据依赖：GET /api/wrong-words（q + type + 日期 AND 组合）。

6.3 仓库页 · 例句（选项卡切换）

  • 列表头部：『例句 · 58 个词条』+ 搜索框（占位『搜索例句』）。
  • 两列收藏卡片网格：每卡为英文句子（14px 加粗）+ 灰色中文翻译（12px，#7A7A7E）。
  • 点击任一收藏卡片 → 弹出「句子结构分析」弹窗（以 I received your letter yesterday. 为第一张卡示例）。

6.4 仓库页 · 辨析（选项卡切换）

  • 列表头部：标题 + 搜索框（占位『搜索收藏的解析』）+ 日期筛选按钮（与先前错误页同款）。
  • 示例卡区：一行 ≥2 张小卡片（本稿 6 张），每张为『辨析词：xx，近义词 xx1 / xx2』。
  • 点击示例卡片 → 弹出「场景辨析」弹窗（560 宽，以 receive 为例：各近义词的适用场景与例句）。

6.5 趋势页

副标题「查看语法正确率与学习曲线」。

  • 语法正确率卡片：标题行『语法正确率』+ 右侧控制组；统计摘要行三组数字——今日 / 平均 / 提升（如 72% → 91%，最后一点实心蓝 + 蓝色数值标注）。
  • 正确率折线图（1080×320）：纵轴 60%–100%，横轴日期（09-11 ~ 09-24），蓝色折线 + 白底蓝边数据点。
  • 错误类型筛选下拉框：收起态（白底圆角 8 + 箭头）→ 展开态菜单（200 宽圆角 12）；选择某一错误类型后，正确率折线图与统计摘要按该类型的句子重新计算。

数据依赖：GET /api/trends?type=&range=，统计源为 check_history。

6.6 辨析页

  • 输入辨析单词 → 出请求（受配置页开关影响，见 7.3）→ 展示辨析结果卡。
  • 结果卡：标题组靠左（如『receive · 3 个易混词』）+ 右侧收藏按钮；正文为各近义词的场景化区分与例句。
  • 历史记录按钮 + 卡片：点击弹出（520 宽统一外壳），5 条历史条目为单词 + 近义词，底部「清空」；点击词条可复用该词的辨析结果（直接回显，不再请求）。

6.7 表达页

中文意译为地道英文。

  • 输入中文句子 → POST /api/express → 展示译法结果。
  • 译法卡：1 张推荐译法卡 + 3 张变体卡（口语 / 书面 / 简洁），每张含场景说明 + 英文例句 + 中文译文。
  • 点击推荐译法或任一变体卡片 → 弹出「句子结构分析」弹窗（以 I received your letter yesterday. 适配演示）。
  • 历史记录按钮 + 卡片：5 条条目为中文原句 → 蓝色英文译法，底部「清空」；点击词条可回填中文并复现译法。

6.8 配置页

副标题「管理当前系统的设置项」。两张全宽设置卡：

  • 设置卡 · 辨析复用历史记录：标题 + 灰色提示『辨析单词前，先查询历史记录是否已存在相同单词；如有，则不必联网查询，复用历史记录。』+ 右侧 Toggle 开关（44×24，开启态蓝底，20×20 白色滑块位于右侧 x:22）。默认开启。
  • 设置卡 · API KEY：密钥输入框（灰底圆角 12）内为掩码 •••••••••••••• + 右侧眼睛按钮（点击显示 / 隐藏明文）；下方提示『密钥仅保存在本地设备，用于请求 LLM 服务；点击右侧按钮可显示 / 隐藏。』

数据依赖：GET / PUT /api/settings；API KEY 写入 SQLite settings 表，不上传。

SECTION 07

通用交互规范

「句子结构分析」弹窗 · 4 个入口

检查页为结果行内嵌卡片（非弹窗）；仓库-先前错误 / 仓库-例句 / 表达页三个入口均为点击卡片弹出，弹窗规格统一：560 宽白卡、发丝线、圆角 18、内边距 24。

「场景辨析」弹窗 · 1 个入口

仅仓库-辨析示例卡片点击触发，560 宽，展示各近义词适用场景与例句。

历史记录卡片 · 统一外壳

宽 520、白底发丝线圆角 18；标题行 = 标题 + 条数 + ✕ 关闭；淡分隔线（#F5F5F7 内缩 20px）；底部清空按钮。三个页面（检查 / 辨析 / 表达）各有一张，条目内容随页面而异；点击条目均可复用回填。

分类选项卡（仓库页）

外壳白底发丝线圆角 999、内边距 4；选项内边距 18×8。激活项蓝底白字 Semi Bold，未激活灰字 Medium；激活与未激活均须为胶囊圆角 999。

搜索框

胶囊形（圆角 999），放大镜图标 14px + 13px 灰色占位；三个占位文案：搜索单词（先前错误）、搜索例句（例句）、搜索收藏的解析（辨析）。输入即过滤，与类型/日期筛选叠加。

下拉筛选

收起态：白底发丝线圆角 8 + 下拉箭头；展开菜单：200 宽、白底发丝线圆角 12、选项间距 2。日期筛选支持预设区间与自定义区间（日历范围选择器）。

Toggle 开关

44×24 胶囊轨道；开 = 蓝底 + 白滑块（20×20）居右（x:22）；关 = 灰底 + 白滑块居左。点击即切换并即时保存 /api/settings。

空状态（建议补充）

列表无数据 / 筛选无结果 / 历史为空时，网格区域显示居中灰字空态提示 +（可选）行动引导；本稿未画空态，验收时按此约定实现。

加载与错误态（建议）

  • LLM 请求期间：检查按钮呈 loading 态（文字可换「检查中…」），结果区禁用重复提交；后端超时 60s。
  • 请求失败：结果卡片行内显示红色错误条（含「重试」），不弹窗打断。
  • API KEY 未配置时调用 LLM 类接口：后端返回明确错误码，前端引导跳转配置页。
SECTION 08

关键交互流程时序

8.1 语法检查主流程

1
输入句子输入框实时字数统计（≤500）；发现过错误后错误词红色高亮常驻
2
触发检查点击「检查」按钮或 Ctrl + Enter；按钮进入 loading
3
后端调用 LLM携带本地 API KEY 请求 → 解析为 翻译 / 错误列表 / 地道表达 / 结构分析，写入 check_history
4
渲染结果结果卡片行两卡并排展示；错误数写入历史芯片
5
加入错词本（可选）红色按钮 → 5s 倒计时（进度环擦除，可点击取消）→ 自动写入错词本

8.2 辨析复用流程（受配置开关控制）

1
输入辨析词前端携带 reuse_history（取自配置页开关）
2
开关开启后端先查 discriminations 本地记录 → 命中同名单词直接返回，不请求 LLM
3
开关关闭 / 未命中请求 LLM → 结果入库 → 返回渲染
4
历史复用历史卡片点词条 → 直接回显该词已有结果
SECTION 09

验收清单

  • 全局：6 项侧边栏导航切换正常，页头标题/副标题与设计稿一致，Token 配色正确（蓝 #0066CC、错误红、绿芯片）。
  • 检查页：字数统计实时；Ctrl+Enter 触发；错误词输入框内红色高亮；结果两卡并排且四个分区齐全；加入错词本 5s 倒计时 + 点击取消 + 自动写入。
  • 检查历史：按钮弹出卡片，条目含错误芯片（红/绿），清空生效，点击条目回填。
  • 仓库-先前错误：类型胶囊点击筛选/再点取消；日期+搜索 AND 组合；计数实时更新；两列网格；点卡片弹「句子结构分析」。
  • 仓库-例句：搜索占位为「搜索例句」；收藏卡为英文加粗 + 灰色中文；点卡片弹「句子结构分析」。
  • 仓库-辨析：搜索占位「搜索收藏的解析」+ 日期筛选；示例卡点击弹「场景辨析」。
  • 趋势页：折线图与统计摘要渲染；错误类型下拉切换后图表按类型重算。
  • 辨析页：结果卡标题靠左 + 收藏；历史卡片点词条复用结果；受配置开关控制。
  • 表达页：推荐译法 + 口语/书面/简洁三变体；点译法卡弹「句子结构分析」；历史点词条回填中文复现译法。
  • 配置页：Toggle 开关状态即时保存并真实影响辨析请求；API KEY 掩码显隐、仅存本地 SQLite。
  • 部署验收：单个可执行文件在个人电脑直接运行，浏览器打开即用；grammar.db 落在本地；卸载仅删文件即数据全清。
验收口径说明：本稿中「生词本」为早期命名，正式术语以 例句 为准（仓库页选项卡为：先前错误 / 例句 / 辨析）。空状态、loading、错误提示三态设计稿未绘制，按第 7 节建议实现。
